# Astra·Sol 협업 규칙

## 적용과 모델 식별

사용자가 요청한 GPT-6.0 Astra는 현재 도구에서 `gpt-6-astra`, GPT-5.6 Sol은 `gpt-5.6-sol`로 선택한다. 이름으로 역할만 붙인 것을 실제 모델 실행으로 보고하지 않는다. 매 세션에서 제공되는 모델 목록을 확인하고 사용할 수 없으면 그 한계를 보고한다.

이 문서는 Harness 역할 분담 지침이다. Local `.codex/agents/astra_reviewer.toml`은 읽기 전용 Astra 설계·리뷰, `.codex/agents/sol_worker.toml`은 부모 권한을 상속하는 Sol 구현 역할이다. 공식 프로젝트 Custom Agent TOML 형식을 사용하며 `.codex/`는 Git 제외한다. 전역 config와 현재 주 Agent 모델·추론 수준은 변경하지 않는다.

새 세션의 Custom Agent 목록에서 astra_reviewer/sol_worker 인식을 확인한 뒤 사용한다. 현재 도구가 Custom Agent 선택 대신 명시적 model만 지원하면 같은 역할 지침을 전달해 위임한다. 모델 변경 시 추론 수준 생략에 대한 도구 동작을 확인하고 수준 변경을 비용 최적화 수단으로 쓰지 않는다. 인식되지 않는 실행 환경에서는 자동 라우터가 설치됐다고 보고하지 않으며, 단일 모델로 진행한 경우 교차 모델 검증은 NOT RUN으로 기록한다.

## 역할과 적용 조건

| 역할 | 기본 모델 | 책임 |
| --- | --- | --- |
| 설계·조정·최종 리뷰 | Astra | 요구사항 충돌, 보안·DB·동시성 판단, 작업 분할, 최종 통합과 완료 판단 |
| 구현·검증 | Sol | 확정된 범위의 Source·Test·문서 수정, 관련 테스트와 실패 분석 |

프로젝트 정책이며 모델의 독점적 능력이나 성능 보장을 뜻하지 않는다. 작은 문서·단일 파일 변경은 현재 모델이 끝낸다. 여러 책임을 가진 기능 또는 고위험 변경에만 협업을 사용하고 리뷰를 위해 필요하면 역할을 바꿀 수 있다. Sol이 주 작업이면 Astra에는 검토할 범위를 제한해 전달한다.

## 실행 Loop

1. 주 담당자가 Harness·관련 계약을 읽고 근거, 목표, 변경 파일과 검증 기준 정리
2. 독립된 작업이 있으면 Sol에 제한된 Context와 파일 소유권을 부여; 계획 미확정 부분은 위임하지 않음
3. 주 담당자는 겹치지 않는 조사·리뷰·검증을 진행하고 같은 파일을 동시에 수정하지 않음
4. 구현 담당자는 작은 변경 → 관련 검증 → 원인 분석 → 수정 Loop 수행
5. 주 담당자는 반환된 diff·명령·결과를 직접 확인하고 통합 검증·Self Review·Diff Review 수행
6. 실패·계약 불일치는 원래 담당자에게 근거와 함께 한 번에 전달, 같은 실패 세 번이면 가설 재검토

주 담당 포함 기본 2개 Agent 이내, 재귀 위임 금지. 다른 Agent의 실행이 끝나기 전 동일 파일 수정 금지. 리뷰 담당자는 기본 읽기 전용이며 직접 고칠 필요가 있으면 파일 소유권을 먼저 인계한다. 별도 사용자 Task 생성, Commit·Push·PR 댓글·운영 변경 권한을 협업 요청에서 유추하지 않는다.

## 인계 양식

```text
목표 / 완료 기준:
담당 파일 / 수정 금지 파일:
확정 결정 / 미확정 사항:
필요한 근거 경로와 절:
실행 명령 / 종료 코드 / 최초 의미 있는 실패:
변경 요약 / 남은 위험:
실제 사용 모델 / 검증 상태:
```

전체 대화·전체 Repository·전체 명세를 복사하지 않는다. Local API 문서는 읽을 경로만 전달하고 Git 추적 인계 문서·PR·모델 설정에 계약 전문을 붙이지 않는다. 다른 worktree에 Local 문서가 없으면 존재한다고 가정하지 않는다. Secret·실제 환경값은 어떤 모델에도 작업 인계용으로 복사하지 않는다.

## Token과 검증 비용

- 관련 파일과 변경점만 전달; 불필요한 전체 대화 fork 피하기
- 동일 범위를 두 모델이 동시에 구현하거나 전체 분석을 반복하지 않음
- 이미 통과한 검증은 해당 변경이 생겼거나 새로운 우려가 확인될 때만 재실행
- 리뷰 결과는 근거·심각도·최소 수정 중심; 긴 추론 과정 출력 요구 금지
- 두 모델의 동의는 테스트 증거를 대체하지 않음
- Token 절감은 Context·중복 작업 축소로 달성하고 추론 수준을 자동 낮추지 않음
- CodeRabbit 설정과 PR Review 요청 정책은 기존 규칙 유지
